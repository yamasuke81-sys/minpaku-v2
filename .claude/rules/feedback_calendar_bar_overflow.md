横カレンダー（`public/js/pages/my-recruitment.js`）の予約バーに要素を足すときは、**1泊バーの幅が1列（`colWN = 36px`）しかない**ことを必ず計算に入れる。バーは「CIセルの50%」から「COセルの50%」までなので、絶対配置の `left: calc(50% + Npx)` は少し足しただけでバーの外へ出る。セルは `overflow:visible` なので、はみ出した要素は**隣の日付セルの上に描画される**＝同日ターンオーバー（前予約のCO＝次予約のCI）のとき次の予約のバー・名簿ドット・人数ラベルに重なる。テラスは1泊予約の連続が多く、この条件は頻繁に起きる。

**Why:** 2026-08-13、やますけの指摘「支払い済みの『¥済』マークが他の予約のバーと表示が重なるのでは？」が的中した。決済バッジを人数ラベルの右隣に `left: calc(50% + 18px + ラベル幅)` で置いていたため、バッジ右端 = `列幅/2 + 約72px` に対しバー右端 = `列幅/2 + 列幅` となり、**列幅が約72px未満のときは必ずはみ出す**。最小列幅は36pxなので、スマホ・標準幅では常に重なっていた。

**How to apply:**
- 予約バーに乗せる要素は**バーの右端へ右寄せ**する（`left: calc(50% + 100% - 3px); transform: translate(-100%, -50%)`。連泊は CI+1 セル基準で `left: calc(-colW/2 + n*colW - 3px)`）。右寄せなら列幅がいくつでもバーから出ない
- そのうえで**収まるかを概算してから出す**: `18(名簿ドット) + 人数ラベル幅 + 4 + 要素幅 + 3 ≤ 泊数 × colWN`。収まらなければ出さない
- 幅が足りない1泊バーでも伝えたい状態は、**幅を取らない表現**（`bookingBarDecor` の上下線）で表す。左右の枠線は使わない — 連泊は日付ごとにセグメントが分かれるので、日付境目に縦線が出てしまう（`unverified` の dashed が上下だけなのはこの理由）
- 既存の**人数ラベルは1泊のとき約8pxはみ出す**（コード内にも「COセル側にはみ出す」と明記）。これは決済バッジ導入より前からの挙動なので、直すときは別途やますけに確認する
- レイアウトの検証はブラウザを立ち上げなくても、**座標式をそのまま移植した静的HTMLを作って目視**すれば足りる（Browser pane は file:// のスクリプトを実行できないので、座標は計算済みで書く）
